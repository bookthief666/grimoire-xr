# 0.49 — Living Reliquary: Returning Reader & Memory Re-entry

Base: exact frozen 0.48 Fold head `201772e41e92275f49208b699126149ee34e149c`.
Tracks issue #59.

## Product intent

The Grimoire already knows how to keep canonical readings. 0.49 makes that memory visible and useful to a returning reader without turning the Threshold into an archive dashboard.

The desired return path is:

**RETURN → RECOGNIZE MEMORY → OPEN DELIBERATELY → CONTINUE READING**

A fresh reader must still see the existing first-minute path first:

**QUESTION → DRAW THREE → WITNESS → READ → KEEP**

## Existing persistence contract to preserve

- `grimoire.xr.reliquary@1` local index.
- Maximum 64 kept readings.
- deterministic reading fingerprint / same-reading upsert.
- exact canonical `ReadingRecord` retention.
- three reading-card relic layers.
- localStorage contains no embedded `data:image/*` payloads.
- IndexedDB artwork payloads fail soft.
- missing artwork never destroys canonical reading truth.
- recurrence is project-derived reading history, never Tarot doctrine.

## Phase A — continuity proof + presentation model

Before any UI activation:

1. prove save → reload using newly-created storage/image-store wrappers over the same persisted backing data;
2. prove exact `ReadingRecord` survival;
3. prove same-reading reseal remains one entry and updates recency/content;
4. prove targeted forget leaves unrelated memories intact;
5. prove corrupt local index fails soft;
6. prove deterministic 64-entry eviction;
7. provide a pure Returning Reader presentation model for latest memory and recurrence-based filtering.

No `App.jsx` or Threshold runtime changes in Phase A.

## Phase B — Threshold re-entry

When kept memories exist, add a compact Living Book memory folio below the primary draw panel:

- `RETURNING READER`;
- most recent question;
- three remembered card titles;
- saved time;
- `OPEN LAST MEMORY`;
- `VIEW RELIQUARY`.

Rules:

- never auto-open or replace a session;
- never obscure the question field or `DRAW THREE`;
- provider-free;
- hidden entirely when the Reliquary is empty;
- session Continuity Return remains a separate higher-priority recovery path.

## Phase C — recurrence navigation

`RETURNING RELICS` becomes interactive history navigation. Selecting a recurring card filters/reveals the kept readings containing it. The UI must repeat that this is derived from the reader's own history and is not a Tarot correspondence or omen claim.
