# 0.46 Scope Freeze

Effective immediately for `agent/0.46-relic-chamber-reliquary`.

Allowed changes:
- fixes required to make the existing Relic Chamber behavior work as specified;
- fixes required to make existing Reliquary persistence/restore/forget behavior safe;
- tests, QA fixtures, verifier corrections, and acceptance documentation for those behaviors;
- accessibility/usability fixes necessary for those same behaviors.

Not allowed until 0.46 is frozen:
- new visual systems;
- new recurrence features beyond already implemented factual recurrence summaries;
- new Spirit behavior;
- new Tarot doctrine/source packs;
- new provider calls;
- new VR behavior;
- ontology migration/runtime work planned for 0.47;
- semantic package extraction planned for 0.48.

Any newly discovered issue outside 0.46 scope is documented and scheduled rather than opportunistically added to this branch unless it is a stop-the-line correctness/data-loss defect.

## Stabilization defects discovered

1. Oracle cards could render and animate while the Chamber callback was absent when a presentation-only `legacyCard` payload was missing.
2. The first regression fixture incorrectly used `card.id || card.canonicalCardId`, masking the real production shape where canonical deck cards carry a numeric legacy `id` and semantic `canonicalCardId`.
3. The production Oracle relic resolver used the same legacy-first identity expression.
4. The resolver activator did not compose with the preceding chamber-open activator because it matched an obsolete handler shape.
5. Reliquary live-layer merge and runtime memory restore also used legacy-first identity expressions.

## Corrected invariants

- Oracle opening is keyed by canonical `cardId`.
- Live deck resolution prefers `canonicalCardId`; legacy string `id` is compatibility fallback only.
- Reliquary live-layer merge prefers canonical identity.
- Reliquary restore indexes and overlays canonical identity first.
- The activation scripts must compose in the documented order and fail closed on an unknown anchor.
- Behavioral tests use the real production deck shape: numeric legacy `id` plus semantic `canonicalCardId`.
