# 0.47 Phase D — Codex Fold UX Stabilization

Issue: #55.

## Scope

Final UX-only stabilization before the 0.47 runtime freeze. Semantic behavior is already accepted on the Samsung Galaxy Z Fold 6.

Phase D does not change Tarot ontology, canonical card facts, relation algorithms, ReadingRecord semantics, persistence authority, provider behavior, or VR code.

## Fold defects addressed

- Codex drawer too narrow for doctrine labels and notes.
- Floating audio control covered Codex controls.
- Reading Doctrine exposed every axis simultaneously, creating a long settings wall.
- Fact-affecting warnings were too dim.
- Doctrine authority summary had insufficient contrast.
- 51 image styles rendered as one always-expanded list.

## UX model

### Codex drawer

- Fold-aware responsive width.
- Sticky header keeps CODEX / close control reachable.
- Floating audio control is hidden only while Codex is open; audio state is unchanged.

### Reading Doctrine

Uses collapsible disclosure sections. Tarot System and Interpretive Lenses open initially; other axes remain one tap away with their selected value visible in the collapsed summary.

Fact-affecting sections display `RECASTS CURRENT READING` while a ReadingRecord is open.

Interpretive lens surfaces continue to state that they cannot alter canonical card facts or relation truth.

### Style Library

The old 51-button scroll wall is replaced by a compact Style Library:

- collapsed by default;
- current style visible while collapsed;
- bounded internal scrolling when open;
- search by name, id, and descriptive prompt text;
- style is explicitly identified as image direction / presentation only;
- selecting a style continues to dispatch the existing `SET_STYLE` action.

Search is a pure presentation function and does not mutate the source catalog.

## Runtime boundary

Phase D modifies only the already-gated local `src/App.jsx` runtime candidate. New support components, tests, scripts, and this document are committed to the support branch.

The complete 0.47 uncommitted runtime candidate therefore remains exactly six files:

- `src/App.jsx`
- `src/reliquary/reliquaryStore.js`
- `src/tarotBridge/archiveEnvelope.js`
- `src/tarotBridge/canonicalTarotBridge.js`
- `src/tarotBridge/oracleSynthesis.js`
- `src/tarotBridge/thresholdReading.js`

`.vercel/` remains explicitly outside the candidate.

## Acceptance evidence

Fold visual acceptance: PASS.

The user reviewed the Phase-D Codex presentation on the Galaxy Z Fold 6 and accepted the widened/collapsible Codex UX and searchable Style Library. Earlier 0.47 physical semantic behavior gates were also accepted: lens-only changes preserve the reading, relation-method changes recast the reading while preserving the question, and Tarot-system changes safely invalidate/rebind while preserving the question.

## Exact freeze gate

Before committing the runtime candidate:

1. run Phase A/B/C/D QA and integration verifiers;
2. run `git diff --check`;
3. run full Vitest + production build;
4. run `npm run qa:ontology:freeze`;
5. stage exactly the six runtime files listed above;
6. run staged diff safety;
7. commit and push that exact Fold-tested runtime.

No 0.48 runtime branch is cut until this freeze commit is pushed.
