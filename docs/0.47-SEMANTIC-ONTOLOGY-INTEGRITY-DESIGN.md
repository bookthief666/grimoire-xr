# 0.47 — Semantic & Ontology Integrity

Status: design contract only. No 0.47 runtime work begins until 0.46 is behaviorally frozen.

## Problem

The visible `Tradition` control currently mixes multiple independent concerns. The canonical bridge already models several of them separately, but the product UI exposes one preset-like choice. Some presets disable correspondence/relation engines, and live switching can leave stale card-label authority attached to a deck produced under a previous system.

## User-facing ontology

### Tarot System
Controls card identity/expression system.

Initial values:
- Thoth
- Rider–Waite–Smith
- Marseille

Changing Tarot System is an identity-authority operation. It must regenerate/rebind visible deck expressions and invalidate stale source-qualified presentation that belongs to the previous system.

### Correspondence Profile
Controls which reviewed correspondence pack is active.

Examples:
- Thoth native
- Golden Dawn
- None / source pack pending

This setting may not silently rename cards.

### Relation Method
Controls deterministic technical relation logic.

Examples:
- Crowley / Liber LXXVIII elemental dignities
- Disabled

This setting must be independently visible when disabled. A lens/theme preset may not silently change it without an explicit user-visible transition.

### Interpretive Lens
Controls model/presentation interpretation only unless a future reviewed source contract explicitly says otherwise.

Examples:
- Jungian Shadow
- Enochian
- Chaos Magick
- Alchemical
- Bruno mnemonic
- Astarte / Venus devotional

Lenses do not become Tarot doctrine and do not alter canonical identity.

### Ritual Theme
Controls atmosphere/presentation only.

Examples:
- None
- Giordano Bruno
- Astarte / Venus

### Reading Depth
Existing Neophyte / Adept / Magus interpretation-depth concept.

### Eros
Content-intensity policy, separate from Tarot system, relation method, and visual current.

## Legacy presets

Existing `TRADITIONS` may remain temporarily as named presets for compatibility. A preset is a convenience macro that expands into the independent axes above; it is not itself the semantic source of truth.

The UI must show what a preset changes before applying it.

## Invariants

1. No live configuration change may leave stale source-qualified card-label authority.
2. No lens/theme selection may silently disable a relation method.
3. Unsupported correspondence packs remain explicit `pending/none`; they are never fabricated.
4. ReadingRecord records the exact axes used for that reading.
5. Restored historical readings preserve their recorded configuration even if current defaults change.
6. Generated interpretation/presentation remains downstream from source-qualified facts.
7. `Tradition` compatibility data can be removed only after archive/session migrations are proven.

## Required regression fixtures

- Thoth + Crowley dignities + no lens → Three Aces FRIENDLY / FRIENDLY, outer INIMICAL.
- Thoth + Crowley dignities + Jungian lens → same deterministic relations; only interpretation lens changes.
- RWS + Golden Dawn + Jungian lens → relation method remains explicit and independent.
- Marseille + no reviewed correspondence/relation pack → explicit disabled/pending state, never inherited Thoth authority.
- Switch Thoth → Marseille in a live session → no Thoth source-qualified display authority survives on the regenerated/rebound deck.
- Restore a historical Thoth ReadingRecord while current app settings are Marseille → reading retains historical Thoth provenance while current global settings remain separate.

## Migration strategy

1. Add a normalized semantic-config object alongside existing `selectedTradition`.
2. Derive that object from legacy presets for old sessions/archives.
3. Move reading/deck construction to normalized axes.
4. Add safe system-switch rebind/regeneration.
5. Expose the new UI progressively.
6. Keep old preset UI only as a compatibility/preset layer.
7. Remove direct semantic dependence on `selectedTradition` only after migration tests pass.

No broad rewrite. No source-pack invention. No archive breakage.
