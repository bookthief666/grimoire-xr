## Governing rule

0.48 starts with executable parity, not shared-package extraction.

The VR contract explicitly requires deterministic cross-client parity to be proven before deciding whether package extraction reduces risk. The current 2D mirror remains migration infrastructure, not an independent source of Tarot truth.

## Phase A — normalized conformance snapshots

Create a client-neutral semantic snapshot shape that contains only shared doctrine:

- contract ID/version and component versions;
- all 78 canonical card IDs in legacy 0..77 order;
- arcana/family/suit-family/rank identity;
- source-qualified Thoth expression fields;
- reviewed Thoth correspondence fields plus source/claim IDs;
- spread IDs and stable position topology;
- supported relation methods;
- canonical source IDs used by relation provenance;
- normalized deterministic fixture outputs.

Explicitly exclude:

- React state;
- Fold UI/layout;
- VR geometry/input/haptics;
- visual current/enchantment;
- generated prose/art;
- provider configuration;
- persistence implementation details.

Both clients should be able to emit this same normalized snapshot from their production semantic data.

## Phase C — 0.47 semantic-axis conformance

0.47 made the Fold client's active configuration orthogonal. 0.48 must prove this remains compatible with the shared Tarot contract without promoting client-only interpretation catalogs into Tarot facts.

Shared axes to compare where represented by both clients:

- Tarot system;
- correspondence profile;
- relation method;
- interpretive lens IDs as configuration vocabulary only, not source facts;
- ritual theme as presentation metadata only;
- reading depth as interpretation-depth metadata only.

Required regressions:

- Thoth + Jungian/Bataille/etc. does not alter Thoth identity/correspondence/relation truth;
- fresh RWS does not claim an unimplemented correspondence pack;
- explicit RWS + Crowley/LXXVIII can use direct relation-method provenance without implying RWS correspondence authority;
- no `thoth_native` relation algorithm exists;
- `UNSPECIFIED` remains a first-class canonical outcome.

## Phase D — de-duplication decision

Only after parity is green, inventory duplicated semantic code by responsibility:

1. canonical identity/index mapping;
2. source-qualified Thoth data;
3. spread topology;
4. relation engine;
5. ReadingRecord construction/normalization;
6. provenance normalization;
7. legacy migration tables.

For each duplicated responsibility choose exactly one of:

- upstream-owned immutable data copied/generated into clients;
- shared pure module/package;
- intentionally client-specific adapter.

Do not extract React/UI, persistence, providers, or VR presentation into the doctrine layer.

## Acceptance gate

Before any shared-package extraction:

- exact 0.47 Fold freeze SHA is recorded;
- exact VR authoritative contract SHA remains recorded;
- normalized snapshot tests pass in both repositories;
- all 78 IDs and reviewed source-qualified claims match;
- Three-Aces fixture matches exactly;
- Major-gap fixture matches exactly;
- contract pin drift fails loudly;
- no provider/presentation fields enter shared truth;
- both repositories pass their existing local full checks.

Only then may a shared-package extraction be proposed as a separate, reversible slice.
