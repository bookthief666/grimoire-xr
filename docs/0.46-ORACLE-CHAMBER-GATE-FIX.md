# 0.46 Oracle → Relic Chamber gate fix

Fold acceptance found that tapping a rendered Thesis / Antithesis / Synthesis relic could produce only the existing visual lift without opening the Relic Chamber.

## Root cause

`OracleLivingBook` attached `onOpen` only when both of these were present:

- canonical `position.cardId`;
- presentation-only `position.legacyCard`.

A restored or sparse canonical reading can preserve a complete ReadingRecord while `reading.cards` is absent or incomplete. `buildOracleBookPresentation()` can still render the card title from the canonical descriptor and the existing hover treatment can still lift the relic, but `legacyCard` is null and the Chamber callback was therefore omitted.

## Corrected invariant

A canonical `cardId` is sufficient to request a Relic Chamber.

`App.jsx` resolves that ID at interaction time in this order:

1. current live deck;
2. current reading card layer;
3. freshly regenerated canonical deck for the active tradition.

Only if all three fail does the app surface an explicit resolution error.

This prevents a presentation-layer compatibility field from becoming an interaction prerequisite and ensures restored ReadingRecords remain interactive.

## Fold fix application

After the normal 0.46 activation:

```bash
node scripts/apply-0.46-oracle-chamber-open-fix.mjs
node scripts/verify-0.46-oracle-chamber-open-fix.mjs
```

The fix remains Fold-gated and does not change Tarot doctrine, ReadingRecord construction, relation calculation, provider behavior, or deck identity.
