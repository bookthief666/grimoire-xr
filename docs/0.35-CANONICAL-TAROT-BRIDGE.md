## Purpose

Bind the existing Fold/2D Grimoire to the same Tarot semantic decisions used by the standalone VR Tarot application without rewriting either application and without creating a premature runtime dependency between repositories.

0.35 keeps the existing local-AI architecture intact:

- Ollama text queue;
- ComfyUI image queue;
- preview/final/refine lifecycle;
- 640x960 preview contract;
- 832x1216 final/refine contract;
- CFG/sampler/scheduler/refine settings;
- Capacitor shell and Fold-specific behavior.

The migration changes what the AI is *allowed to decide*, not the GPU/render configuration.

## Oracle synthesis boundary

`src/tarotBridge/oracleSynthesis.js`

The prior application flow asked the language model to infer Elemental Dignities from three generated card names.

The 0.35 flow is:

`cloth/deck -> canonical card IDs -> deterministic ReadingRecord relation facts -> source-qualified synthesis prompt -> Ollama/Gemini prose`

The model is explicitly forbidden to:

- recalculate dignity relations;
- fill `UNSPECIFIED` source gaps;
- replace canonical card identity with a generated manifestation name;
- alter canonical reason codes or provenance;
- invent a `thoth_native` dignity method.

The prompt deliberately retains the phrase `Synthesize a 300-word divinatory answer using Elemental Dignities` so the existing server-side structured Oracle task inference remains compatible. No server queue rewrite is needed for this bounded pass.

## Physical/2D cloth continuity

For a completed TRIAD, the cards physically arranged by the user in `spreadSlots` become the consultation cards.

Only when the TRIAD cloth is incomplete does the existing three-card random fallback remain available.

This fixes the previous discontinuity where the user could arrange cards on the cloth and the Oracle would then ignore them and draw a different random three-card set.

## Forge / image-generation boundary

`src/tarotPrompt.js` now accepts optional `canonicalContext`.

When a source-qualified Thoth context is active, prompt order is:

1. canonical card ID;
2. canonical Thoth expression;
3. reviewed canonical correspondence fields;
4. explicit canonicality rule;
5. invocation / visual / generated interpretive material;
6. model-generated legacy Meta fields, labeled `NON-CANONICAL`;
7. art direction and render constraints.

The existing text model may still produce the UI's Hebrew/planet/alchemical/daimon `meta` object, but those values are now explicitly interpretive unless the canonical bridge separately verifies the same field.

## App activation

Because `src/App.jsx` remains a roughly 97k single-file surface, the integration is applied with a guarded deterministic migration rather than an uncontrolled whole-file rewrite:

```bash
node scripts/apply-0.35-canonical-tarot-bridge.mjs
```

The migration:

- refuses to run if reviewed parent markers have drifted;
- is idempotent;
- adds canonical IDs to new 78-card decks;
- removes the random-sort Oracle path;
- routes completed TRIAD cloth cards into the canonical consultation;
- computes relation facts before calling the model;
- stores `readingRecord` and `selectionSource` with the reading payload;
- supplies canonical context to Forge image prompts;
- labels generated metadata as `MODEL_GENERATED_REFLECTION`;
- does not modify ComfyUI/provider/render settings.

The migration is intentionally not wired into `npm run build`; source code must never self-modify as a hidden build side effect.
