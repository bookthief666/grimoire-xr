# 0.47 — Semantic & Ontology Integrity

Base: exact accepted 0.46 runtime `bc56a63773a4e41751f3fc1121fa6f07666e4bc1`.

Issue contract: #53.

## Why this milestone exists

The legacy `selectedTradition` control conflates independent concerns:

- Tarot system identity;
- correspondence source pack/profile;
- inter-card relation method;
- interpretive lens;
- ritual theme;
- reading/explanation depth.

That coupling allows an interpretive choice such as Jungian Shadow, Bruno, or Astarte to silently change or disable Tarot-system authority. It also allows `SET_TRADITION` to change a label while leaving a live deck/reading bound to stale authority.

0.47 fixes that correctness defect before further product expansion.

## New semantic configuration

Schema: `grimoire.semantic.config@1`.

Orthogonal axes:

1. `tarotSystem`
   - `thoth`
   - `rws`
   - `marseille`
2. `correspondenceProfile`
   - `thoth_native`
   - `none`
3. `relationMethod`
   - `crowley_lxxviii_dignities`
   - `disabled`
4. `interpretiveLenses`
   - zero or more project-authored lenses such as Jungian, Bruno, Astarte, alchemical, etc.
5. `ritualTheme`
   - presentation/ritual framing; never a Tarot source fact.
6. `readingDepth`
   - `neophyte`, `adept`, `magus`.

Eros remains separate from semantic Tarot configuration.

## Fresh defaults

### Thoth

- system: `thoth`
- correspondences: `thoth_native`
- relation method: `crowley_lxxviii_dignities`

### Rider-Waite-Smith

- system: `rws`
- correspondences: `none`
- relation method: `disabled`

The project does not currently contain a reviewed Golden Dawn/RWS correspondence pack equivalent in authority to the Thoth pack, so a fresh RWS config must not claim one.

Crowley/Liber LXXVIII dignities may be selected explicitly as a relation method without implying an RWS correspondence pack.

### Marseille

- system: `marseille`
- correspondences: `none`
- relation method: `disabled`

No source-qualified Marseille correspondence/relation pack is invented by this milestone.

## Legacy compatibility

`TRADITIONS` remains only as a migration/input-compatibility vocabulary until runtime integration is complete.

Legacy sessions migrate deterministically:

- prior RWS relation behavior may be retained explicitly as `crowley_lxxviii_dignities`;
- the old hidden `golden_dawn` correspondence claim is not retained because no reviewed source pack currently backs it;
- Bruno/Astarte/Jungian/etc. become lenses/themes instead of Tarot systems;
- historical `ReadingRecord` objects are never rewritten by session migration.

## Transition rules

### Tarot-system change

- rebuild the canonical 78-card deck for the target system;
- preserve canonical card IDs;
- preserve creative/user-history layers such as artwork, exegesis, generation state, and patina;
- rebuild display labels/authority from the target system;
- strip stale system-specific authority fields;
- clear focused card;
- invalidate the open reading;
- stop an in-flight consultation state.

### Correspondence-profile change

- do not rewrite card identity;
- clear focused card authority surface;
- invalidate the open reading.

### Relation-method change

- do not rebuild card identity;
- invalidate the open reading;
- focused card may remain open because card identity/correspondence authority did not change.

### Lens/theme/depth change

- do not rebuild deck identity;
- do not change correspondence authority;
- do not change relation method;
- do not invalidate the current canonical reading solely because presentation/interpretation settings changed.

## Authority-safe deck rebuild

A system transition keys cards by `canonicalCardId` first. For truly old numeric-only cards, the canonical 78-card legacy-index bijection is used as compatibility fallback.

The transition strips stale fields including active-system expression/correspondence/source qualification before target-system deck genesis is applied.

This prevents a manifested Thoth relic from remaining `THE MAGUS`, `DISKS`, or Thoth-source-qualified after switching the active system to RWS.

## Development phases

### Phase A — semantic kernel (current)

- versioned config model;
- legacy preset migrator;
- transition planner;
- authority-safe deck rebuild;
- session migration helper;
- Vitest + CLI QA.

No `App.jsx` runtime changes in Phase A.

### Phase B — canonical bridge integration

- bridge accepts `semanticConfig` directly;
- legacy `tradition` argument remains temporary compatibility input;
- ReadingRecord input records the orthogonal axes;
- Threshold and Oracle synthesis consume the new config;
- no generated provider is allowed to recalculate facts.

### Phase C — app/persistence/UI integration

- state gains semantic config;
- old sessions migrate on restore;
- reducer uses tested transition planner;
- overloaded TRADITION selector is replaced by orthogonal controls;
- provider persona/tone uses lens/theme without becoming Tarot authority;
- physical Fold behavioral gate proves system transition, reading invalidation, lens independence, persistence, and restore.

## Behavioral acceptance

Required before 0.47 freeze:

- Thoth -> RWS keeps 78 canonical IDs but changes active presentation authority (`THE MAGUS` -> `THE MAGICIAN`, `DISKS` -> `COINS` where applicable);
- no active Thoth source qualification survives that transition;
- generated image/exegesis/patina survive the identity-safe rebuild;
- Jungian lens on Thoth leaves Crowley dignities active;
- Bruno/Astarte lens/theme does not change Tarot system or relation method;
- relation-method change invalidates the open reading;
- legacy sessions migrate deterministically;
- old ReadingRecords restore unchanged;
- `npm run qa:ontology`, `npm run check`, and Fold behavioral gate pass.

## Explicit non-goals

0.47 does **not**:

- add new Tarot source packs;
- research/claim Golden Dawn or Marseille facts;
- extract the shared cross-client doctrine package;
- add new visual spectacle;
- add VR features;
- merge or deploy.

0.48 owns cross-client conformance and doctrine de-duplication.
